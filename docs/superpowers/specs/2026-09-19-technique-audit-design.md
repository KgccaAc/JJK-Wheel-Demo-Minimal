# 全术式审计统合设计

## 目标

对项目当前全部术式进行可复跑、可追溯的平衡审计，并为每个术式和其关联牌给出数值调整方案。审计只使用项目真实战斗逻辑，不恢复已经移除的 AP 机制，不访问或写入正式服务器。

## 审计粒度

### 1. 术式家族级

按 `WheelTechniqueRegistry` 的 canonical key、角色 `cardTags`/`traits` 和 `domainId` 建立家族索引。输出家族定位、关联角色、关联牌数量、准备/兑现/领域结构、资源档位、两回合伤害/生存/节奏表现，以及与同角色基础牌的差异。

### 2. 术式链级

将同一术式的资源生成、前置准备、兑现、召唤、反制和领域视为一条链。评估每一步的前置条件、失败率、CE 机会成本、窗口延迟、组合收益和断链风险。领域按激活回合及后续至少一回合的窗口评估，不以激活回合即时伤害为唯一价值。

### 3. 单牌级

覆盖每张带术式匹配标签、术式特殊效果、领域定义或术式专属召唤的牌。记录源字段值和 DSL/atomic effect 实际解析值，包含 CE、HP 成本、伤害、治疗、护盾/格挡、状态、召唤、命中率、风险和前置条件。每张牌必须有真实样本，或记录明确的缺失原因，不能把缺失样本当作零价值。

## 数据流

1. 读取 `cards.json`、`characters.json`、`rules.json` 和 `WheelTechniqueRegistry.gd`，构建稳定索引。
2. 对每个术式家族选择可运行角色与对照角色，调用真实 `BattleFlowSession`、`ActionResolverV3`、`RoundResolverV3` 和牌池服务。
3. 使用固定种子和配对场景，分别运行低 CE（最大值约 25%）、正常 CE（初始值）、高 CE/领域场景；每场记录至少两回合状态。
4. 输出原始 JSON，再生成 Markdown 汇总和逐术式调整方案。报告引用样本数、种子、运行时版本和缺失原因。

## 核心指标

- 可用率：单牌和最多三牌合法组合在各 CE 档位的通过率。
- 资源效率：实际 CE 消耗、每点 CE 的有效 HP 伤害/避免伤害/恢复量/状态价值。
- 节奏：激活延迟、两回合有效伤害、TTK 变化、领域窗口收益。
- 可靠性：命中率、前置失败率、目标无效率、自损和反制暴露。
- 组合：准备牌到兑现牌的转化率、断链率、同回合占用和牌手选择机会成本。
- 牌组表现：角色完整牌组的低/中/高资源可行动率、伤害分布、方差和异常尾部。

## 价值预算

审计使用统一诊断式：

`总价值 = 即时伤害 + 防御/治疗 + 状态 + 未来回合 + 组合收益 - CE 成本 - 前置折扣 - 命中/风险折扣`

该式用于解释差异，不替代真实结算。不同效果必须按可比窗口折算；例如治疗先制造伤口再测净恢复，领域按激活后窗口测量。

## 调整方案格式

每个术式家族和每张术式牌输出：当前问题、严重度（P0/P1/P2/观察）、当前源值、实际解析值、建议值或建议区间、调整理由、预期两回合 TTK/资源影响、副作用和复测场景。运行时未生效或样本不足时，优先标记为实现/测量问题，不提出伪数值修正。

## 验收边界

- 84 个角色、351 张牌和所有注册术式均出现在索引或缺失清单中。
- 报告中的每个结论带样本数和固定种子集合。
- Godot 脚本解析通过，固定种子审计可重复运行。
- AP 清理验收继续通过，审计不重新引入 AP 字段或校验。
- 首轮只生成建议和少量基准复测，不批量改动牌面数值。
