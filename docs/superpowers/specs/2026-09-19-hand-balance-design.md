# 手牌战斗平衡修复设计（无 AP 方案）

日期：2026-09-19
状态：已获用户继续实施授权，进入实施前规格冻结
范围：本地基础战斗、故事模式、转盘角色基础战斗、联机客户端兼容；联机服务器协议不变，仅预览链路回归

## 1. 玩家目标

玩家在首回合应能快速理解“我能出什么、为什么现在出、还剩多少资源”，并在保留熟练玩家组合空间的同时，避免因历史 AP 字段、费用覆盖或前置条件导致“看似能出、实际不能出”。

## 2. 非目标与边界

- 不重做 351 张牌的内容平衡，不在第一阶段批量改 cards.json 数值。
- 不改变正式服，不写入正式服务器，不改变联机协议字段、revision、phase、winner 语义。
- 不把 10 张手牌立即改成 8 张；先以真实“最多选择 3 张 + CE/前置条件”为基线，再用统计结果决定第二阶段。
- 不新增普通灰色 Button 或临时 UI 控件；费用提示复用现有卡牌展示。

## 3. 规则冻结

### 3.1 资源与出牌限制

- AP 是历史残留，不是当前战斗资源；卡牌源数据、模板和手牌注入不再携带 AP。
- 当前合法性只由最多选择 3 张、CE、命中/目标、状态前置和领域每回合最多 1 张共同决定。
- 旧客户端带来的 AP 字段在实例化边界丢弃，不参与校验、扣费或 UI 展示。
- 已提交的选择在预览阶段不扣资源；通过校验并进入结算后一次性扣除 CE，避免双扣。

### 3.2 CE 展示与结算

- resolved_cost.ce 是唯一结算值。
- 卡牌 UI 必须使用同一个 resolved view model 显示 CE；不能同时显示未经 DSL 解析的源值和结算值。
- 若需要显示源值，明确标注“基础”，否则只显示 resolved 值。
- resolved 失败时采用源卡值并给出诊断，不允许显示空值或 0。

### 3.3 手牌结构

- 第一阶段保持当前 10 张发牌、固定弃 2 张、最多选择 3 张的外部流程，以降低故事/联机回归风险。
- 规则源文件只保留当前手牌语义的注释/字段；不再引入 ap_budget，避免把历史 AP 重新变成第二套行动门槛。

### 3.4 组合与可行动性

- 合法组合生成必须先过滤：可用性、前置条件、CE、领域限制。
- 至少保留单牌、双牌组合；三牌组合只受最多选择 3 张、CE、目标和前置条件约束。
- UI 预览必须在选择变化后显示剩余 CE，并解释不可用原因，而不是只显示“已选 N 张”。

## 4. AI 评分

AI 分两阶段：

1. 可行性过滤：排除 CE 超限、目标不合法、前置不满足、领域重复。
2. 评分：utility = immediate_damage + 0.6*healing + 0.5*block + 0.35*state_value + 0.2*combo_value + 0.1*future_value - 0.15*ce。

所有分量归一化到 0..100；命中率低于 50% 的攻击降权；能完成角色术式核心标签的组合获得 combo bonus；不得为了静态伤害选择不可结算组合。

## 5. 伤害乘区

第一阶段不重写所有牌面公式，只增加 trace/边界：

final = Base * (1 + additive_character_strategy) * status_multiplier * domain_multiplier -> defense/shield

- 角色与策略同类增益合并，软上限 ±40%。
- 易伤/减伤合并为单一状态乘区，初始范围 0.70..1.35。
- 领域仅保留一个独立乘区，默认范围 0.85..1.25，并记录领域负荷。
- 暴击、必中、无视防御是稀有标记，不再作为普通增伤重复乘算。
- 每个 action result 输出可选的 damage_trace，便于验收和策划调参。

## 6. 错误处理与兼容

- 旧牌含 AP：在数据加载边界丢弃并在开发日志中标记 legacy_ap_discarded。
- cost 类型异常：该牌不可选，显示明确原因；不让异常穿透到 resolver 崩溃。
- 联机协议不新增 AP 字段；服务器继续以 CE、前置和权威状态校验。
- 规则校验失败时回合安全失败，不扣资源、不推进 phase。

## 7. 验收指标

固定种子 20 局、故事/转盘角色各至少 5 局、联机预览至少 2 局：

- 首回合至少 6/10 张牌可用；至少 2 种决策类型。
- 首回合至少 2 种合法组合；不得出现 CE 不足或前置不满足的组合被结算。
- UI resolved CE 与结算 trace 差异为 0。
- 连续两回合无法行动比例 < 5%。
- 主题牌首回合出现率 20%..40%。
- 最高/中位伤害倍率比 2.5..3.0；超出只记录红灯，不私自压平内容。
- 故事首牌、四条核心流程、联机 revision/phase/winner 回归通过。

## 8. 实施顺序

1. 先新增红灯验收和固定种子统计工具。
2. 清理卡牌/模板 AP 字段与 V3 AP 校验。
3. 统一 resolved 费用 view model 与 UI。
4. 改进 AI 可行性过滤和评分。
5. 增加 damage trace/乘区边界（不改变协议必填字段）。
6. 跑 Godot headless、真实窗口、故事流程、转盘角色战斗、预览联机回归。
7. 根据统计决定是否进入 B/C 第二阶段。
