# 第一章逐页制作规格

## 0. 玩家结果与范围

玩家应当感觉自己先通过转盘得到一个不可预测但完整的角色，再选择是否把这个角色投入一条可读、可重复、能真实战斗的故事线。第一章的情绪曲线是“期待签名会 -> 记忆断裂的不安 -> 在仙台做出第一个主动选择 -> 从地图读懂主线 -> 以真实战斗承担风险 -> 结算并看到成长”。

本轮范围是从身份判定完成到第一章节点结算。普通节点使用本地隐式规则，AI入口只保留协议；关键节点使用原始剧情盘/手动选择/战斗，AI不拥有关键跳转权。

## 1. 全局流程状态机

```text
WHEEL_DRAWING
  -> IDENTITY_REVIEW
  -> MODE_SELECT
  -> STORY_HOME
  -> RPG_INTRO
  -> SELECTION_SLOT
  -> MAP
  -> {SELECTION_SLOT | RPG_NODE | BATTLE}
  -> SETTLEMENT
  -> MAP / HOME
```

`StoryState` 是故事权威状态；页面只读/提交命令。每次提交生成 `pending_result`，结算页确认后才写入 `history` 和 `current_node`，避免中途返回重复奖励。全局转场由 `StoryTransition` 提供：输入锁定 -> 旧页淡出/黑屏 -> 切场 -> 新页淡入；减少动画设置时只保留 0.08 秒遮罩。

## 2. 页面规格

### 2.1 转盘页 `wheel.tscn`

- **职责**：完成角色判定；不得直接跳过身份小结算。
- **玩家动作**：抽取、调整动画时序、查看本轮结果、确认保存角色。
- **状态写入**：保存 `wheel_rank`、原始 answers、traits、techniques、剧情开始时期到 `AppSession`；确认后进入 `identity`。
- **反馈**：抽取中禁用抽取/评级；转盘停止后显示分数和六维摘要，再允许确认。
- **转场**：评级确认后使用全局短淡出切到 identity；返回不会丢失已保存角色。
- **验收**：抽取中不能重复提交；刷新/返回后角色快照仍可展示；没有绕过 identity 的入口。

### 2.2 身份小结 `identity.tscn`

- **职责**：把六维结果翻译成可读角色卡，是故事入口的“确认仪式”。
- **展示**：姓名/时期/阵营/术式/评级；资源与六项成长分组；变化值用 `+/-` 颜色标识；折叠的“原始判定”供查看。
- **按钮**：保存角色（幂等）、下一步；下一步必须确认快照有效。
- **动画**：角色卡先入场，评级印章延迟 180ms 落下，数值条从 0 补间到目标；下一步点击后按钮锁定并淡出。
- **失败路径**：缺少快照显示“返回转盘”，不允许进入故事。

### 2.3 分流页 `Select.tscn`

- **职责**：明确“继续转盘”和“故事模式”是两条不同的游玩循环。
- **动作**：两张大卡本身就是确认按钮；“继续转盘”返回当前转盘，“沉浸故事”进入故事设置，返回保留角色。
- **动画**：悬停轻微抬升，按下脉冲，全局遮罩接管切页，避免误触造成双跳。
- **验收**：故事入口不会直接进入 RPG 以外的旧 Demo；转盘入口回到当前角色上下文。

### 2.4 故事设置 `StroyHome.tscn`

- **职责**：选择本章可用难度和剧情实现方式。
- **当前开放**：故事模式难度 Easy；基础剧情与 AI 普通节点模式均可选择。Normal/Hard 仍显示锁定原因；AI 只影响普通节点叙事，核心节点不可使用 AI。
- **动作**：难度/模式是单选；开始游戏写入 `StoryState.configure_story`，回转盘不清状态。
- **动画**：选中纹理即时替换并有 0.12 秒脉冲；锁定项点击只显示说明，不触发导航。
- **验收**：刷新后默认回到 Easy/基础；模式标记可被后续 Selection 读取。

### 2.5 通用 RPG `RPG.tscn`

- **职责**：承载固定对白、角色发言、背景、关键选择和可复用节点脚本。
- **第一章内容**：签名会 -> 缝合额头 -> 玻璃破碎/束缚 -> 黑屏 -> 仙台路牌 -> 记忆疼痛。
- **动作**：下一句、关键选择、跳过；跳过仅允许跳到当前节点安全出口，不结算奖励。
- **动画**：每行文字淡入；1-6 背景按段落切换；穿越段落播放玻璃音效、0.35 秒闪白后 0.45 秒黑屏，再切 Selection。
- **验收**：重复点击不会跳过两行；跳过与正常结束的结果相同但历史标记不同；场景可被后续节点复用。

### 2.6 普通交互 `selection.tscn`

- **职责**：把一个普通节点拆成早上、中午、下午、晚上四个时间槽，形成一日内的小型剧情。
- **动作**：每个时间槽都从观察/交谈/搜索/休息中手动选择一次；基础模式读取本地表，AI模式允许输入自定义行动。AI响应只保留白名单资源/成长增量和叙事文本，provider 不可用或响应非法时自动回退本地表。
- **规则**：`chapter1.json` 为四个行动分别配置四段文本、资源变化和成长变化。节点内只做预览与累计，前三次确认推进时间，第四次才生成一个 pending result；资源、成长、剧情旗标、物品和 NPC 关系都会累计到这一次结果，统一交给 `StoryState` 提交；隐式转盘不改关键节点 ID。
- **动画**：行动卡用成对选中纹理；前三次行动后显示“时间推进·中午/下午/晚上”的暗色短遮罩；晚上结束后进入统一结算。
- **验收**：16个本地结果均有文本和资源字段；四段经历只提交一次；剧情旗标与物品不会在四时段合并时丢失；中途返回不发放累计奖励；固定模式不遮挡行动卡。

### 2.7 地图 `Map.tscn`

- **职责**：唯一的主线推进页；展示章节、可达节点、角色当前资源和经历入口。
- **节点**：第一章开放剧情、战斗和完成节点；突发、分支和高危图标作为后续内容预览并保持锁定。按钮到节点、前置条件和场景路径来自 `chapter1.json`。
- **动作**：点节点查看详情，再点进入节点；锁定节点只说明条件；查看经历打开只读日志；读取存档恢复最近确认状态。
- **动画**：节点选中纹理切换并沿路线高亮；进入节点时地图缩小到 0.98 后淡出；回到地图保留上次选中节点。
- **验收**：锁定节点不能进入；剧情节点进入通用 RPG，战斗节点进入 battle；完成节点说明章节结束；地图状态与 StoryState 一致。

### 2.8 战斗 `battle_scene.tscn`

- **职责**：复用现有真实战斗，不在故事页模拟战斗结果。
- **注入**：进入前由 StoryState 提供完整转盘角色快照；通过现有 `LoginCardCharacterProjector -> BattleEligibility -> CardCandidateBuilder -> HandDealer` 生成角色资源、术式牌、标签牌和领域牌。故事节点只额外指定敌方角色、章节和难度。
- **反馈**：战斗胜负、死亡、撤退都必须有明确结果；返回键在战斗中禁用或弹出确认。
- **出口**：结果适配器写入 pending result，统一进入 settlement；失败可重试但不重复消费资源。故事战斗禁止替换成固定角色代理。

### 2.9 统一结算 `settlement.tscn`

- **职责**：所有事件/剧情/战斗的唯一奖励提交点。
- **展示**：结果标签、资源变化、成长变化、路线变化、节点回顾、记录保存状态；数值按“变化 -> 当前值”展示。
- **动作**：继续回地图、查看完整经历、返回首页；继续按钮在保存完成前禁用。
- **动画**：成功标签落下 -> 资源数字滚动 -> 成长条补间 -> 继续按钮显现；失败结果使用同一布局但颜色和文案不同。
- **验收**：刷新/重复点击不重复奖励；回地图后节点状态更新；完整经历包含本次节点和结果。

## 3. 数据与接口

`StoryNode`：`id,type,title,prerequisites,entry_scene,exit_scene,source_wheel_ids,choices,result_rules,next`。

`StoryCommand`：`node_id,action_id,mode,seed,input,payload`。

`StoryResult`：`outcome,resource_delta,growth_delta,flags,log,next_node,source`。

接口边界：`StoryState.begin_node()`、`resolve_local(command)`、`submit_pending(result)`、`commit_pending()`、`discard_pending()`；`BattleStoryAdapter.start(context)` / `finish(result)`；`StoryTransition.play(path, style)`。

## 4. 第一章主线

`chapter1_intro`（固定 RPG） -> `chapter1_selection`（四时段普通交互） -> 统一结算 -> `chapter1_map`（主线地图） -> `chapter1_clue`（预设桥接剧情与有限选择） -> 统一结算 -> `chapter1_battle`（河岸低级咒灵，真实战斗） -> 统一结算 -> `chapter1_end`。

第一章的河岸事件是教学桥接，不伪装成原转盘核心剧情。结束后明确对接原始主线的 W145「是否加入高专」。从“剧情开始时期”到“涩谷事变完成”的不可 AI 核心节点已逐项抄录到 `data/story/core-timeline-main-start-shibuya.json`；后续章节只允许由该表中的转盘、有限选择或真实战斗决定核心结果。

普通节点结果只改变资源/成长/线索；`chapter1_clue` 的分支必须由原始 flow-v1 对应 wheel 条目或手动选项产生；AI只能生成描述和非关键小事件。

## 5. 质量门

- **流程**：每个页面可独立启动，主链可从角色判定走到结算。
- **状态**：命令幂等、奖励只提交一次、返回/重载不丢确认状态。
- **视觉**：所有 actionable 控件有 hover/focus/pressed/disabled 的可辨反馈；动画支持减少动效。
- **内容**：节点文本、按钮、下一节点和 `chapter1.json` 一致。
- **证据**：Godot parse/headless、纯逻辑测试、真实窗口路径截图、战斗胜负/返回/重复点击回归。
